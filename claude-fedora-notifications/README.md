# Claude Code → нативные уведомления KDE/Plasma (Fedora)

Аналог [WSL-версии](../claude-wsl-notifications/), но под **Fedora KDE Plasma (Wayland)**.
Нативные баннеры Plasma, когда Claude Code **нужно твоё действие** — поверх любого окна,
с повторными напоминаниями и авто-заголовком из имени чата.

## Что показывает

| Событие | Баннер |
|---|---|
| Запрос разрешения | **‹имя чата›** · `❓ Разрешить — Bash · git push origin main` |
| Напоминание (раз в минуту) | `‼️ ожидается действие (напоминание #N): …` |
| Задача завершена (ход ≥45 c) | `✅ Готово — Claude закончил (за 2м 13с)` |
| Ожидание ввода / MCP-форма | `💬 Claude ждёт твоего ответа` / `📝 Нужен ввод` *(только в терминал-режиме)* |

- **Заголовок** баннера — авто-название чата Claude (из транскрипта), фолбэк — `Claude Code — ‹папка›`.
- **Поведение**: баннер всплывает, **сам уходит через ~5 c**, и **повторяется раз в минуту**
  (максимум 20 раз ≈ 20 мин), пока не отреагируешь. На каждом повторе обновляется ОДИН баннер.
- **Звук**: по умолчанию **выключен**. `CC_SOUND=1` — всегда со звуком.

## Чем отличается от Windows-версии (и почему)

Окружение здесь — **VSCode во Flatpak-песочнице** на **KDE Wayland**. Из этого следует:

- **Доставка через прямой D-Bus, а не `notify-send`.** В песочнице `notify-send` идёт через
  portal, который теряет срочность/таймаут и кладёт уведомление сразу в *историю*, минуя баннер.
  Поэтому шлём напрямую в `org.freedesktop.Notifications.Notify` через `gdbus` — так баннер
  всплывает корректно. Заголовок баннера = поле `summary`.
- **Нет «тихо, когда ты в VSCode».** Определить активное окно из песочницы нельзя:
  `org.kde.KWin` не виден на шине Flatpak, а Wayland в принципе запрещает запрос активного окна.
  Поэтому звук — глобальный тумблер (`CC_SOUND`), а не по фокусу.
- **Нет клика по баннеру для открытия чата.** Схема `vscode://` из Flatpak не зарегистрирована
  как обработчик; надёжного способа нет, поэтому клик-открытие убрано.
- **`expire_timeout`** выставлен явно (по умолчанию 5000 мс): `0` по спецификации = «висеть вечно»,
  поэтому без явного таймаута баннер не уходил сам.
- **Повтор «на месте»** реализован через `CloseNotification(старый id)` + новый `Notify`
  (Plasma 6 игнорирует `replaces_id` для уже показанного/истёкшего уведомления и плодит дубли).

## Требования

- Fedora с графической сессией (тестировалось на **KDE Plasma 6 / Wayland**)
- `python3`, `gdbus` (пакет `glib2`), `setsid` (пакет `util-linux`)
- Claude Code (CLI или VSCode-расширение)

## Установка

```bash
./install.sh
```

Затем **полностью перезапусти VSCode** (закрой окно и открой). ⚠ Обязательно —
хуки читаются на старте сессии, а правки в живой сессии Claude Code затирает
своим автосейвом разрешений.

## Удаление

```bash
./uninstall.sh
```

## Настройка (необязательно)

Переменные в блоке `"env"` файла `~/.claude/settings.json`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CC_NOTIFY_INTERVAL` | `60` | период повторов, сек |
| `CC_NOTIFY_MAX` | `20` | сколько раз напоминать |
| `CC_DONE_MIN_SECONDS` | `45` | мин. длина хода для баннера «Готово» (`0` = на каждый ход) |
| `CC_NOTIFY_EXPIRE` | `5000` | через сколько мс баннер сам уходит (`0` = висит, пока не закроешь) |
| `CC_SOUND` | `0` | `1` — проигрывать звук на каждом баннере |

```json
"env": { "CC_NOTIFY_INTERVAL": "90", "CC_SOUND": "1" }
```

## Важно знать про VSCode-расширение (native UI)

- Расширение **глотает** хук `Notification`, но исправно вызывает `PermissionRequest` —
  поэтому уведомление о запросе разрешения работает. Реально срабатывают: запрос
  разрешения, повторы, «Готово».
- Уведомление об **idle/ожидании ввода** и MCP-формы работают только в терминал-режиме
  (`"claudeCode.useTerminal": true`) или в чистом CLI.

## Состав

```
hooks/
  notify-linux.sh    Notification + PermissionRequest → баннер + маркер + цикл повторов
  notify-pretool.sh  PreToolUse → запоминает запрашиваемую команду/файл
  notify-clear.sh    UserPromptSubmit + PostToolUse → гасит повторы (+ старт хода)
  notify-stop.sh     Stop → баннер «Готово» после долгого хода
  _notify.sh         отрисовка одного баннера через прямой gdbus Notify (+ закрытие старого)
  _reminder.sh       фоновый цикл повторных напоминаний
install.sh / uninstall.sh
```

## Баннеры падают сразу в «Историю», не всплывают?

- Проверь **«Не беспокоить»** (значок в трее / `Параметры → Уведомления`).
- В `Параметры → Уведомления → Настройки приложений` у приложения не должно стоять
  «Показывать только в истории».
- Баннер всплывает на `PopupTimeout` (по умолчанию 3 c) — это норм, повторы вернут его.
